# Миграция Беньки: OpenClaw → Hermes Agent на VPS Hermes

## 1. Результат и график

Перенести агента, знания и действующие сценарии в новый Git-репозиторий и на существующий VPS Hermes. Сохранить историю Git, переработать интеграции под Hermes и предоставить Telegram, CLI и веб-панель.

**Разработка и переключение разделены. Сначала полностью готовим код, миграторы, конфигурацию и тесты Hermes. После этого OpenClaw продолжает обслуживать все рабочие сценарии ещё примерно две недели. Переключение выполняется позже, только по отдельной команде Дениса.**

| Период | OpenClaw | Hermes |
|---|---|---|
| Подготовка | Продолжает работать | Разработка, тесты, установка изолированного кандидата |
| Около двух недель ожидания | Единственная производственная система | Код готов; производственные подключения и расписания выключены |
| Отдельная команда Дениса | Остановка на время финального переноса | Свежий импорт состояния, проверки и включение |
| После переключения | Остановлен, сохранён для отката | Работает; минимум 48 часов наблюдения |

Истечение двух недель **не запускает переключение автоматически**.

Сохраняем Obsidian, LightRAG, Syncthing, Redis и OmniRoute. Историю разговоров переносим в защищённый архив с поиском; в Hermes начинаем новые сессии.

**Статус документа:** согласованный план. Перечисленные ниже действия и критерии не являются отчётом о выполнении; готовность подтверждается отдельным протоколом проверок.

**Реализация:** [eiler2005/my-ai-office](https://github.com/eiler2005/my-ai-office), приватный репозиторий. Текущий статус и фактические проверки — в [протоколе](hermes/acceptance.md); сведения о VPS — в [реестре](hermes/inventory.md). Переключение production не выполнено.

План основан на локальных файлах проекта и официальной документации Hermes, проверенной 2026-09-06. Перед исполнением необходимо подтвердить актуальное состояние обоих VPS.

## 2. Целевая архитектура

### Уточнение целевого VPS из reddit-compass

- Цель — HostKey `vps-hostkey-hermes`; доступ получать через
  `vps_management/ansible/scripts/ssh-vps.sh --host vps-hostkey-hermes`.
  IP, пользователь и ключ разрешаются wrapper-скриптом из защищённого vault;
  не дублировать их в этом документе или новом Git-репозитории.
- Это общий сервер с действующими стеками `reddit-compass`, `cheap-intelligence`,
  `moex-futoi` и `stealth`. Каталоги, данные, Compose и cron соседних проектов
  исключены из изменений этой миграции.
- По документации Reddit Compass порт 80 используется для ACME, 443 принадлежит
  L4/SNI-роутеру `router_configuration`, а 8450 — HTTPS Reddit Compass.
  Не переносить старый Caddy с захватом 80/443 и не менять существующую SNI-маршрутизацию.
- Для Беньки выделить `/opt/benka-hermes`, собственную Docker-сеть и тома;
  предпочтительный HTTPS-порт панели — 8451, только после проверки занятости.
  Панель публиковать через собственный Caddy с TLS/mTLS; сертификат предоставлять
  отдельно, без попытки занять чужой порт ACME. Служебные порты — loopback/private network.
- Уточнение Дениса от 2026-09-06: использовать домен Reddit Compass или рядом, не нарушая его работу.
  Выбран существующий `RC_PUBLIC_HOST` с отдельным портом 8451 и копией действующего сертификата;
  адрес и доступы сохраняются только в закрытом manifest. Детали — `docs/hermes/panel.md`.
- Исторический снимок от 2026-08-01: 8 CPU, около 15 GiB RAM и диск около 157 GiB.
  Это не текущий capacity gate: перед установкой и переключением повторить замеры,
  учитывая соседние batch-задачи и лимиты памяти.
- Источники: `reddit-compass/docs/HOSTING.md`, `reddit-compass/deploy/hostkey/README.md`,
  `vps_management/docs/ownership-matrix.md` и `vps_management/docs/containers.md`.

| Компонент | Реализация после переноса |
|---|---|
| Бенька | Hermes Gateway с адаптированными личностью, инструкциями, навыками и профилем пользователя |
| Telegram | Существующий бот, чаты и темы; маршрутизация и разрешения по доверенным идентификаторам |
| Личная и рабочая почта | Интеграции Hermes с сохранением опроса, фильтрации, определения исходного отправителя и actionable/informational triage |
| Telegram Digest | Интеграция Hermes с Telethon; прежние источники, папки, курсоры, оценка, баланс категорий и ссылки |
| Signals / Last30Days | Прежние правила, источники, пресеты и дедупликация под управлением Hermes |
| Knowledgebase / Ideas | Инструменты Hermes поверх ядра `wiki-import`, с сохранением wiki-first поведения |
| LightRAG | Перенесённые граф и данные; сохранён локальный embedding endpoint `wiki-import` |
| Redis | Streams, события, курсоры, дедупликация и восстановление незавершённых заданий |
| OmniRoute | Сохранённые маршруты соответствующих нагрузок |
| Syncthing | Подключение Mac к новому серверу после финального переноса и сверки vault |
| Управление | Hermes CLI и отдельный процесс веб-панели за Caddy, TLS/mTLS и аутентификацией |

**Код интеграций.** Создать Python-пакет `benka-integrations`: инструменты и команды Hermes, сценарии cron и обработчики Redis. Заменить старые HTTP-мосты и OpenClaw-обвязки новым runtime интеграций. Проверенные алгоритмы обработки и их тесты использовать повторно. Расширения регистрировать через систему плагинов Hermes. [Плагины Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins)

**Вызовы моделей.** Заменить `docker exec ... openclaw agent` адаптером на Python API Hermes. Для фоновых задач создавать отдельный `AIAgent`, отключать личную память и контекстные файлы, ограничивать инструменты, итерации и время выполнения. Сохранить валидаторы результатов и детерминированные резервные результаты при отказе LLM. [Python API Hermes](https://hermes-agent.nousresearch.com/docs/guides/python-library)

**Интерфейсы и состояние.**

- Сохранить смысл `wiki_ingest`, `wiki_read`, `wiki_lint`, `lightrag_query`; добавить запуск сценария, проверку статуса и поиск по архиву.
- Сохранить wiki-поля `source_type`, `source`, `capture_mode`, `promote_fingerprint` и результаты `wiki_page_paths`, `raw_path`, `rag_status`.
- На первом этапе сохранить форматы Redis-событий и существующего состояния для совместимости переноса и отката.
- Разделить personal, work, family и sandbox: ограничения действуют для инструментов, файлов, памяти и сборки контекста.

**Расписания и доставка.** После переключения Hermes cron становится единственным владельцем расписаний приложения. Фиксированные скрипты ставят задания в Redis; обработчики выполняют работу и фиксируют результат. Для таких заданий отключить автоматическую доставку cron. Использовать общий модуль поверх `hermes send --json`, сохранять подтверждённые идентификаторы сообщений; неопределённые отправки направлять на сверку без слепого повторения. [Cron без агента](https://hermes-agent.nousresearch.com/docs/guides/cron-script-only), [доставка сообщений](https://hermes-agent.nousresearch.com/docs/guides/pipe-script-output)

**Память.** В компактную память Hermes перенести устойчивые сведения и профиль. Полные дневники и разговоры оставить в архиве; wiki сохраняет роль основного хранилища знаний, LightRAG — поискового слоя. [Память Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)

## 3. Этапы выполнения

### A. Инвентаризация без остановки OpenClaw

- Проверить оба VPS: ОС, архитектуру, ресурсы, диски, контейнеры, сети, порты, тома, права, фоновые процессы и соседние сервисы.
- Зафиксировать работающие версии и image digest. Незавершённое обновление OpenClaw не включать в перенос.
- Сопоставить Git HEAD, незакоммиченные изменения и серверные файлы; определить точный исходный набор.
- Составить реестр: функция → реализация Hermes → переносимое состояние → проверка приёмки.
- Собрать расписания из OpenClaw cron, системного cron и внутренних планировщиков, включая обслуживание wiki и LightRAG.
- Перечислить необходимые секреты по назначению, без значений.

**Результат:** реестры компонентов, функций, данных, расписаний и препятствий к переносу.

### B. Полностью подготовить код и новый репозиторий

- Создать отдельный checkout с историей, ветками и тегами; старый remote оставить без изменений.
- Проверить историю и выбранные текущие изменения на секреты. При обнаружении утечки остановить публикацию до устранения.
- Новый remote по умолчанию сделать приватным; URL задаётся параметром `<NEW_REPO_URL>`.
- Исключить из Git `.env`, Hermes auth/state, Telethon sessions, архивы, vault, Redis и LightRAG.
- Реализовать интеграции, адаптеры, конфигурацию, Docker Compose и процедуры установки, импорта, проверки и отката.
- Подготовить миграторы для финального свежего состояния, включая повторный безопасный запуск и отчёт о пропущенных объектах.
- Обновить README, CHANGELOG и эксплуатационные инструкции.
- Commit и push выполнять после отдельного подтверждения согласно правилам проекта.

**Результат:** готовый код Hermes и проверенные миграторы; производственная система продолжает работать на OpenClaw.

### C. Подготовить VPS Hermes и провести репетицию

- Сохранить сведения о существующих сервисах целевого VPS; выделить отдельные каталоги и Compose-проект.
- Размещать Hermes и runtime-зависимости в контейнерах, без Docker socket и административного доступа агента к хосту.
- Зафиксировать версии и зависимости; настроить постоянное хранилище, лимиты ресурсов, перезапуск и ротацию логов.
- Подготовить веб-панель, Caddy и TLS/mTLS. Проверить аутентификацию и WebSocket через прокси. [Веб-панель Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/web-dashboard)
- Провести репетицию импорта на обезличенных fixtures и доступной проверенной резервной копии. Не копировать работающие БД как обычные файлы.
- Telegram проверить с отдельным тестовым ботом и тестовыми темами.
- Проверить восстановление после неудачного импорта и повторный запуск мигратора.
- Производственные бот, почтовые опросы, Telethon, рассылки и расписания на Hermes оставить выключенными.
- Тестовый vault не подключать к производственному Syncthing.

**Результат:** статус `READY_NOT_ACTIVE` — код, миграторы, конфигурация и репетиционные проверки готовы; Hermes ещё не обслуживает production.

### D. Период ожидания — примерно две недели

- OpenClaw остаётся единственным владельцем производственного polling, расписаний, рассылок и записи данных.
- Hermes-кандидат сохраняется с фиксированной версией кода и зависимостей. Автодеплой и автоматическое переключение выключены.
- Продолжается обычное резервное копирование OpenClaw.
- Все изменения исходного проекта за этот период — исправления, новые функции, расписания, источники, настройки и ротации секретов — отмечаются в журнале расхождений.
- Изменения поведения переносить в Hermes-кандидат и проверять соответствующими тестами.
- Обычные новые письма, сообщения, заметки и курсоры накапливаются только в производственной системе. Они будут перенесены финальным снимком.
- Репетиционный снимок не считается актуальным производственным состоянием и не используется для включения Hermes без обновления.

**Выход из этапа:** отдельная команда Дениса на переключение. До неё OpenClaw работает независимо от длительности ожидания.

### E. Повторная проверка непосредственно перед переключением

- Повторно снять инвентаризацию и закрыть журнал расхождений за время ожидания.
- Проверить доступы, актуальность секретов, OAuth, источников и моделей.
- Подтвердить готовность окончательного кода и повторить тесты затронутых изменений.
- Измерениями подтвердить достаточность диска, RAM и времени для копирования и восстановления.
- Проверить доступность Mac, резервного хранилища и SSH-маршрута.
- Подготовить чистое производственное состояние Hermes отдельно от результатов репетиции.
- Если обнаружен незакрытый функциональный пробел, оставить OpenClaw работающим и устранить его до начала окна.

### F. Финальный перенос в согласованное окно

1. Запретить новые задания OpenClaw и дождаться завершения активных; записать незавершённые задачи и неопределённые отправки.
2. Остановить только относящиеся к миграции планировщики, Gateway, обработчики и процессы записи. Приостановить Syncthing с обеих сторон.
3. Зафиксировать Telegram update watermark, Telethon cursors, почтовые watermark, Redis pending entries и подтверждённые доставки.
4. Создать **свежую согласованную холодную копию**, включающую все изменения за недели ожидания: OpenClaw, workspace, vault, интеграции, Redis, LightRAG, OmniRoute, конфигурацию и секреты.
5. Потоково сохранить архив в защищённом каталоге Mac; проверить состав, SHA-256 и восстановление. Сохранить образы и конфигурацию старого сервера.
6. Восстановить данные на VPS Hermes с правильными владельцами, правами и томами.
7. Для импортера собрать отдельный OpenClaw layout: в текущем развёртывании config и workspace разделены. Выполнить `hermes claw migrate --dry-run` с `--source` и пресетом `user-data`, затем импортировать проверенные личность, навыки и компактную память.
8. Применить подготовленные адаптации инструкций, cron, плагинов и привязок каналов. Штатный импорт не восстанавливает все эти возможности автоматически. [Импорт из OpenClaw](https://hermes-agent.nousresearch.com/docs/guides/migrate-from-openclaw)
9. Настроить секреты и OAuth поддерживаемыми способами Hermes; проверить модели, embeddings, wiki и очереди.
10. Включить единственный производственный Telegram polling-процесс Hermes и выполнить ручные проверки.
11. Включить расписания и обработку накопившихся данных.
12. Подключить Syncthing с новой идентичностью устройства после сверки vault и отсутствия неожиданных удалений.

Существующий скрипт обновления Gateway не использовать как готовый мигратор всего стека. Соседние проекты на обоих VPS не останавливать.

**Расписания для исходной сверки, Europe/Moscow:** Telegram Digest — 08/11/14/17/21; личная почта — 08/13/16/20; рабочая — восемь слотов 08:30–19:00; опрос почты и Signals — каждые пять минут; Last30Days — 07:00; LightRAG — каждые 30 минут. Добавить ежедневное и еженедельное обслуживание wiki. Итоговый источник — подтверждённый серверный реестр перед переключением.

## 4. Проверки и критерии готовности

| Проверка | Условие успеха |
|---|---|
| Регрессии | Поведенческие тесты обработки данных проходят после замены runtime |
| Репетиция миграции | Импорт, повторный запуск, прерывание и восстановление проверены на изолированных данных |
| Изменения за период ожидания | Все новые функции и настройки OpenClaw учтены в Hermes-кандидате |
| Личность и архив | Сохранены стиль и устойчивые сведения; старые разговоры доступны через поиск с источником |
| Telegram | Ручное сообщение и follow-up дают входящее событие и ответ в нужной теме |
| Разрешения | Неавторизованные пользователи отклоняются; personal/work/family/sandbox разделены |
| Почта | Работают оба ящика, пересылки, triage и дедупликация; полные письма не индексируются по умолчанию |
| Telegram Digest | Сохранены источники, папки, курсоры, баланс категорий и ссылки |
| Signals / Last30Days | Работают правила и оба пресета; отказ отдельного источника не ломает весь выпуск |
| Модели | Проверены primary, каждый резерв, таймауты, ошибки авторизации, некорректные ответы и отказ всех LLM |
| Knowledgebase | Поиск использует базу; сохранение создаёт wiki-страницу; `обсуди:` не сохраняет сообщение |
| Ideas | Capture создаёт страницу; promotion обновляет существующую цепочку без дубля |
| LightRAG | Контрольные запросы находят ожидаемые страницы; embedding-модель и размерность сохранены |
| Cron и Redis | Один запуск на слот; повторная обработка безопасна; pending entries восстанавливаются |
| Веб-панель | Работают вход, чат, WebSocket, сессии и настройки; неавторизованный доступ отклоняется |
| Надёжность | Перезапуск и перезагрузка восстанавливают систему; нет OOM, циклов рестартов и растущей очереди |
| Откат | Проверен возврат на старый runtime до и после появления новых записей |

До переключения использовать fixtures, тестового бота и контролируемые отказы. Провести совместный нагрузочный прогон Telegram-запроса, дайджеста и индексации.

После переключения наблюдать минимум **48 часов**, получить реальные запуски всех ежедневных сценариев и проверить еженедельное обслуживание на копии данных. Успешный health-check сам по себе не закрывает функциональную приёмку.

## 5. Откат и завершение

**Основания для отката:** отсутствует Telegram ingress, нарушены темы или разрешения, обнаружены потеря данных, повторные публикации, неработающая база знаний либо нестабильный runtime.

**До новых производственных записей:** остановить Hermes и обработчики, вернуть старый стек из состояния непосредственно перед переключением.

**После новых записей:** остановить новую систему и сохранить её состояние. Перенести обратно новые wiki-артефакты, подтверждённые доставки, курсоры и совместимые состояния очередей; архивировать новые диалоги Hermes. Сверить pending entries и неопределённые отправки перед включением старых обработчиков. Не заменять актуальные данные первоначальным архивом без сверки изменений.

**Допущения и ограничения:**

- Существующие бот, темы, источники и модели сохраняются; отключённые функции автоматически не включаются.
- Адреса VPS, URL репозитория, домен панели и секреты задаются в закрытом deployment manifest.
